## Overview

### Tech Lead Evaluation Rubric - Core Evaluation (90 Points)

Performance will be evaluated across four key areas that reflect the multifaceted nature of technical leadership in agile software development teams building open source products. This rubric emphasizes human-centered growth mindset, cultivating an inclusive culture of curiosity and technical excellence.

## Weight Distribution:

- 35% (31.5 points) - Managing Team Dynamics
- 35% (31.5 points) - Software Engineering Quality
- 15% (13.5 points) - Product and Project Management
- 15% (13.5 points) - Implementing Open Source Practices

### **Assessment Philosophy**

Evaluation incorporates instructor observation of all communications and codebase, peer feedback, client input, review of project management artifacts and checkpoint documents, and evidence of community engagement. Focus is on growth trajectory, learning from mistakes, and cultivating both technical excellence and human-centered leadership.

### **Legacy Codebase Context**

Tech Leads are often building on legacy codebases and inheriting existing product documentation and open source practices. Performance will be evaluated not just on the current state of artifacts, but on what the Tech Lead is actively doing to shape things toward a better state. The emphasis is on demonstrating improvement, strategic refactoring, and progressive enhancement of inherited systems.

## 1. Managing Team Dynamics (35% - 31.5 points)

This is the "Lead" in "Tech Lead" - evaluated through all team communications including Slack, email, in-person meetings, GitHub comments, and every interaction (or lack thereof) with Developers and Contributors.

### **Sub-components:**

**Ensuring Active and Open Communication** Maintains transparent, frequent communication channels; proactively shares context and decisions; removes information silos; ensures developers are never blocked by lack of communication; models responsive engagement across all platforms
**Facilitating Collaborative Development** Creates psychologically safe environment for experimentation and learning; encourages diverse perspectives; enables effective pair/mob programming sessions
**Client Relationship Management** Conducts productive client meetings; translates client needs into actionable insights; maintains transparent communication loops
**Leading Retrospectives** Facilitates reflection on team processes; drives actionable improvements; models vulnerability and growth mindset
**Fostering Inclusive Team Culture** Actively cultivates curiosity; celebrates learning from failures; ensures all voices are heard; addresses power dynamics constructively
**Conflict Resolution & Team Health** Navigates interpersonal challenges with empathy; recognizes and addresses burnout; promotes sustainable pace

## 2. Software Engineering Quality (35% - 31.5 points)

This is the "Tech" in "Tech Lead" - evaluated through direct codebase review. The Tech Lead influences code quality with every piece of code they accept into the repository.
**When inheriting legacy code:** Evaluation focuses on the Tech Lead's strategy for improving code quality over time - identifying technical debt, prioritizing refactoring efforts, and ensuring new code raises the bar rather than perpetuating existing problems.

### **Sub-components:**

**Modular Architecture & Component Design** Enforces discrete, modular component structures with clear boundaries; implements loosely-coupled systems; designs for independent component evolution; ensures code can be understood and modified in isolation
**Code Maintainability & Readability** Accepts only code that future developers can understand; writes self-documenting code; maintains consistent conventions; ensures technical debt is visible and managed strategically; prioritizes clarity over cleverness
**Testing Practices** Implements comprehensive test coverage (unit, integration, e2e); writes testable code; uses TDD/BDD appropriately; ensures tests serve as documentation
**Code Review Culture** Provides constructive, growth-oriented feedback; models learning through reviews; ensures reviews enhance code quality and knowledge sharing; holds the line on quality standards
**Continuous Integration/Delivery** Establishes automated CI/CD pipelines; maintains deployment readiness; implements effective branching strategies; ensures code is always in releasable state
**Technical Decision Documentation** Records architectural decisions (ADRs); explains trade-offs transparently; maintains living documentation that explains the "why" behind code structure

## 3. Product and Project Management (15% - 13.5 points)

The Tech Lead must articulate a coherent product vision that is clear to everyone - Client, Developers, and Contributors. Evaluated through project management tools and checkpoint documents. This pillar documents the final deliverables and is critical for maintaining throughline and enabling smooth handoffs between Tech Leads.
**When inheriting existing product documentation:** Evaluation focuses on how the Tech Lead synthesizes, clarifies, and evolves inherited product direction - identifying gaps, resolving ambiguities, and building coherent narrative from fragmented or outdated materials.

### **Sub-components:**

**Product Vision Articulation & Communication** Develops and consistently communicates compelling long-term product direction; ensures vision is understood and internalized by all stakeholders; creates coherent narrative that connects daily work to strategic goals
**Continuous Discovery** Conducts ongoing user research; validates assumptions through experimentation; integrates learning into product decisions; documents discovery insights
**Project Management Tool Usage** Effectively uses project management tools (issue tracking, boards, milestones) to make product direction visible and actionable; maintains clear view of progress and priorities
**Checkpoint Documentation & Handoff Materials** Delivers strategic product documents (vision statements, roadmaps, strategy artifacts, handoff documentation); demonstrates evolution of product thinking over time; creates materials that enable future Tech Leads to continue the work seamlessly
**Sprint Planning & Execution** Facilitates effective sprint planning; balances discovery and delivery work; uses project management techniques to maintain momentum while advancing toward vision
**Product Pitching** Articulates product value propositions clearly; tells compelling product stories; adapts communication for different audiences

## 4. Implementing Open Source Practices (15% - 13.5 points)

The Tech Lead is the de-facto maintainer of an open source product. No one else is responsible for engaging with the wider open source community or embracing Contributors.
**When inheriting existing open source practices:** Evaluation focuses on how the Tech Lead assesses current state, addresses gaps in baseline expectations, and moves the project toward stronger community engagement - not on the inherited state alone.

### **Baseline Expectations (required - Tech Lead is directly accountable):**

**OSI License Compliance** Selects and correctly applies OSI-approved license; ensures dependency license compatibility; Tech Lead is responsible for all licensing decisions
**Essential Documentation** Maintains README, CONTRIBUTING, CODE_OF_CONDUCT; provides clear setup instructions; ensures documentation welcomes and enables external contributors
**Community Governance** Establishes contribution workflow; defines decision-making process; implements issue/PR templates; creates clear pathways for external participation
**Maintainer Responsiveness** Responds to external issues and PRs promptly; provides clear feedback to contributors; ensures welcoming first-contributor experience; owns all community interactions

### **Advanced Practices (bonus consideration - demonstrates strong open source engagement):**

**Active Community Building** Cultivates external contributors; mentors newcomers; promotes project in relevant communities; builds sustainable contributor base
**Governance Maturity** Implements transparent governance model; documents maintainer responsibilities; establishes clear escalation paths; enables distributed maintainership
**Upstream Contributions** Demonstrates meaningful engagement with upstream projects; contributes back to dependencies; participates in broader open source ecosystem
**Community Health & Growth** Tracks and improves contributor diversity; monitors community sentiment; celebrates community achievements; grows project visibility and impact

## Evaluation Sources

Assessment will incorporate:
- Instructor observation and review of work products
- Review of all team communications (Slack, email, GitHub, meetings)
- Direct codebase review
- Peer feedback from team members and other Tech Leads
- Client input on collaboration and delivery effectiveness
- Review of project management tools and checkpoint documents
- Evidence of community engagement and professional growth
