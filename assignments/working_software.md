**Due:** End of Iteration (Sprint 7/Launch Sprint)
**Focus:** Functional Software Delivery

## Overview

The most important deliverable is functional software that satisfies both client needs and program standards. This means software that solves real problems for your client while meeting open source community standards for quality, documentation, and maintainability.
Working software demonstrates your ability to lead a team through complex technical challenges while balancing competing priorities.

## Requirements

Your software must:
- **Function:** Work as intended without critical bugs
- **Solve real problems:** Address actual client/user needs validated through discovery
- **Meet quality standards:** Follow established code quality practices, include appropriate tests
- **Be documented:** Include README, setup instructions, architecture documentation, and inline code documentation
- **Be maintainable:** Use clear patterns, reasonable abstractions, and sustainable practices
- **Follow open source standards:** Include proper licensing, contribution guidelines, and community documentation
- **Be deployable:** Include deployment documentation or working deployment

## Deliverables

- The product's GitHub repository will be used as a starting point to find how to run and use the software.

## Evaluation Criteria

## Functionality

- Software works without critical bugs
- Core features deliver intended value
- User experience is functional and usable

## Code Quality

- Clean, readable, maintainable code
- Appropriate testing
- Sustainable engineering practices

## Documentation

- Clear README and setup instructions
- Architecture and technical documentation
- Open source community documentation (contributing guidelines, code of conduct, etc.)

## Client/User Value

- Software solves validated user problems
- Delivers meaningful value to client/users
- Addresses requirements from discovery work

## Open Source Standards

- Proper licensing
- Community-ready documentation
- Contribution-ready repository structure

## Notes

- This is the foundation of everything else - strategy documents and presentations mean nothing without working software
- "Working" means functional and delivering value, not perfect or feature-complete
- Quality and maintainability matter as much as functionality
- Open source standards are not optional extras
