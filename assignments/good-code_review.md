## Deliverable

- Pull request URL that you gave a review on
- Evidence of substantive technical engagement on major technical aspects:
- data structures
- algorithms
- module architecture
- automated testing
- understandability
- technical debt
- ...

## Review Guidelines

- Review all lines of code, but only comment on lines with major issues
- Reviews should be constructive: highlight strengths and provide actionable feedback on concerns
- If there are no major technical issues, provide positive feedback on the implementation
- The PR itself should contain sufficient evidence of review dialogue and feedback incorporation

## Evaluation

- Substantive engagement - evidence of meaningful participation in the code review process (1 point)
- Code review quality - technical value of the review, focus on major issues (1 point)
- Communication quality - clear articulation of ideas, use of code review good practices (1 point)
*Note: Feedback incorporation will be evaluated individually based on how each developer responded to and incorporated feedback on their own work.*
